# Running WasteWise on IBM LinuxONE (s390x)

Everything in this file was observed on the LinuxONE Community Cloud VM used for
the IBM Datathon (17 Oct 2026). Raw output is regenerated by
`scripts/capture_evidence.sh` into `evidence/`.

## The machine

| Item | Value (from `lscpu`, `/proc/cpuinfo`) |
|---|---|
| Architecture | s390x, **big-endian** |
| Machine type | **9175** = IBM z17 / LinuxONE Emperor 5 (Telum II processor) |
| CPU flags | include `nnpa` (Neural Network Processing Assist = on-chip AI accelerator) |
| vCPUs / RAM | 3 / 7.8 GiB, under z/VM 7.3.0 |
| OS / Python | Ubuntu 24.04.4 LTS, kernel 6.8, Python 3.12.3 |
| zDNN | `libzdnn0` 1.0.1 (Ubuntu); `zdnn_is_nnpa_installed()` returns True |

## Where each library came from

PyPI has **no s390x wheels for CPython 3.12** for numpy, scipy, pandas,
scikit-learn, pyarrow, LightGBM, XGBoost or onnxruntime (checked with
`pip download --only-binary :all:`). Solutions used:

| Package | Version | Source on s390x |
|---|---|---|
| numpy, scipy, pandas, scikit-learn, pillow | 1.26.4, 1.11.4, 2.1.4, 1.4.1.post1, 10.2.0 | Ubuntu 24.04 s390x packages (`apt`), seen through a `--system-site-packages` venv and pinned with `constraints-s390x.txt` |
| pyarrow (needed by Streamlit) | 24.0.0 | Built from the Apache Arrow source release (SHA-512 verified) by `scripts/vm_build_pyarrow.sh`: Arrow C++ about 5 min, pyarrow about 2 min on 3 vCPUs |
| IBM Snap ML | 1.17.2 | Native `manylinux_2_28_s390x` wheel from PyPI |
| Streamlit, Plotly | 1.66.0, 7.1.0 | Pure-Python wheels |

## Telum accelerator

Snap ML picks its accelerator build (`libsnapmllocal3_zdnn`) only if
`libzdnn` can be loaded. Without it, Snap ML prints *"Falling back to CPU-only
mode. IBM Snap ML will not leverage NNPA."* Installing `libzdnn0` fixed this
on this VM. `wastewise.platform_info` reports the machine type, the `nnpa`
flag and the zDNN check, and the UI header shows the result.
